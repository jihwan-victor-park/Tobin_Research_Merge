# 우리 스크레이퍼는 어떻게 작동하나 — 교수님 설명용

> 미리보기: **Cmd+Shift+V**

---

## 한 문장
> **"사이트마다 구조가 다르니까, 쉬운 곳은 전용 코드로 긁고, 어려운 곳은 AI 에이전트가 알아서 방법을 찾아내요. 그리고 실패하면 스스로 고쳐요."**

---

## 1. 왜 이렇게 만들었나

VC 포트폴리오 사이트 400곳을 긁으려는데, **사이트마다 구조가 전부 달라요.**
- 어떤 곳은 JSON API를 그냥 열어둠
- 어떤 곳은 JavaScript로 그려서 HTML엔 아무것도 없음
- 어떤 곳은 "더 보기" 버튼을 눌러야 나옴

400개를 사람이 하나씩 코딩하면 몇 달 걸리고, 사이트가 개편되면 다시 깨져요.
그래서 **2단계(tier) 구조**로 만들었어요.

---

## 2. 2단계 구조

```
                    스크레이핑 요청
                          |
              ┌───────────┴───────────┐
              v                       v
     ┌─────────────────┐     ┌─────────────────┐
     │  EASY (쉬움)     │     │  HARD (어려움)   │
     │  전용 코드 35개   │     │  AI 에이전트      │
     └─────────────────┘     └─────────────────┘
     Y Combinator            나머지 모든 사이트
     Techstars               (등록 안 된 곳은
     a16z, Sequoia…           자동으로 여기로)
```

### EASY — 손으로 짠 전용 스크레이퍼 (35개 사이트)
큰 곳(YC, Techstars, a16z, Sequoia 등)은 **한 번 제대로 짜두면 안정적**이라 직접 코딩했어요.
사이트 구조에 따라 4가지 패턴을 씁니다:

| 패턴 | 뜻 | 예 |
|---|---|---|
| `api_direct` | 숨은 JSON API를 직접 호출 | Greylock, Founders Fund |
| `bs_single` | HTML 한 장 파싱 | USV, BVP, a16z |
| `bs_paginated` | 페이지 넘기며 수집 | HuggingFace |
| `playwright` | 실제 브라우저를 띄워서 JS 렌더링 | Balderton |

### HARD — AI 에이전트가 알아서 (나머지 전부)
등록 안 된 사이트는 **자동으로 여기로** 넘어갑니다. Claude + Tavily 검색을 써서 **2단계로** 시도해요:

**1) 빠른 경로**: 페이지를 가져와서 → Claude가 "여기서 회사 목록 뽑아줘" → 끝 (대부분 여기서 성공)

**2) 안 되면 에이전트 모드**: Claude가 **스스로 도구를 골라 가며** 탐색합니다
```
전략 순서: single_page_extract  (한 장에서 뽑기)
        → subpage_discovery   (하위 페이지 찾아 들어가기)
        → pagination_probe    (페이지 넘김 시도)
        → search_probe        (사이트 내 검색 시도)
```

## 3. ⭐ 핵심: 스스로 배우고 고쳐요

### (a) 성공하면 "방법"을 기억합니다
어떤 사이트를 성공적으로 긁으면, **그 방법을 YAML 파일로 저장**해요.
다음에 같은 사이트에 가면 **처음부터 다시 헤매지 않고** 저장된 방법을 씁니다.

> 지금까지 **410개 사이트의 공략법**이 쌓여 있어요.

```yaml
# 예: data/scrape_instructions/kakao.vc.yaml
domain: kakao.vc
preferred_strategy: single_page_extract     # ← 이 방법이 통했다
seed_urls: [https://www.kakao.vc/en]
last_success:
  record_count: 123                         # ← 123개 회사를 수확
  valid_name_ratio: 1.0
```

### (b) 실패하면 스스로 승급/차단합니다 (HEALER)
```
쉬운 스크레이퍼가 2번 연속 실패  →  자동으로 AI 에이전트한테 넘김
AI 에이전트도 3번 연속 실패      →  90일간 그 사이트 제외 (자원 낭비 방지)
```
그리고 **왜 실패했는지 한 줄 진단**을 DB에 적어둡니다.

## 4. 스크레이퍼 말고 다른 수집 경로도 있어요

포트폴리오 사이트 스크레이핑은 4개 경로 중 하나일 뿐입니다:

| 경로 | 방법 | 특징 |
|---|---|---|
| **포트폴리오 스크레이핑** | 위에 설명한 2단계 구조 | VC·액셀러레이터·대학 400곳 |
| **GitHub 발굴** | GitHub API로 AI 저장소 주간 스캔 | 상용 DB에 등록되기 **전** 단계 포착 |
| **정부 그랜트** | NIH·NSF SBIR/STTR 공개 API | 연방 R&D 지원받은 실제 기업 |
| **뉴스** | 전 세계 스타트업 미디어 RSS 18개 | 투자·창업 소식에서 회사 추출 |

## 5. 실제 성과 (현재 Railway DB)

| 지표 | 값 |
|---|---|
| 등록·추적 중인 사이트 | **296곳** |
| 학습된 공략법 파일 | **410개** |
| 총 스크래핑 실행 | 882회 |
| 포트폴리오에서 수확한 회사 | **33,844개** |
| 뉴스에서 추출 | 446건 |

**사이트 상태:** 정상 108 · 불안정 36 · 실패 132 · 대기 16 · 제외 4

**성공률:** 쉬운 티어 **69%** (63/91) · AI 에이전트 티어 **23%** (182/791)

> ⚠️ AI 에이전트 실패가 많은 건 **대부분 Anthropic API 크레딧이 떨어져서**였습니다
> (크레딧이 있을 때는 정상 작동). 그리고 애초에 **어려운 사이트만** 여기로 오기 때문에
> 성공률이 낮은 게 정상입니다 — 쉬운 곳은 이미 전용 코드가 처리하니까요.

## 6. 교수님 질문에 대한 답 ("좋은 정보를 찾는 방법이 있나?")

**있습니다. 3가지 원칙으로 만들었어요:**

1. **비용 순서대로** — 싼 방법 먼저, 안 되면 비싼 방법 (전용코드 → AI에이전트 → 웹검색)
2. **한 번 배우면 재사용** — 성공한 방법을 저장해서 다음엔 공짜로
3. **실패를 기록하고 포기할 줄 앎** — 3번 실패하면 90일 제외해서 자원 낭비 안 함

**한계도 명확합니다:**
- 로그인이 필요한 사이트는 못 긁습니다
- JavaScript가 매우 복잡한 사이트는 실패율이 높습니다
- 사이트가 개편되면 다시 배워야 합니다 (자동으로 감지는 됩니다)
