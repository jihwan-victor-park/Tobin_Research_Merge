# 스크래핑 확장 계획 (depth + breadth)

> 목표 두 가지
> 1. **Depth** — 기존 hidden 회사의 세부정보를 더 채운다
> 2. **Breadth** — hidden 회사 자체를 더 발굴한다

---

## 0. 먼저: 앞선 추정치 정정

전에 "미등록 yaml 195곳 → 약 14,000개 수확"이라고 했는데 **틀렸다.**
195개 파일을 전부 열어보니:

| | 파일 수 | 성공 이력 있음 | 저장된 평균 수확 |
|---|---|---|---|
| 등록된 사이트 | 215 | 194 (90%) | 24건/사이트 |
| **미등록 사이트** | **195** | **26 (13%)** | 18건/사이트 |

**yaml 파일은 "공략법"이 아니라 "시도 기록"이었다.** 실패해도 파일이 생긴다.
→ 미등록 195곳 중 **실제로 돌릴 가치가 있는 건 26곳(~500개 수확)**뿐.

그리고 에이전트 티어 사이트의 실제 수확량은 **사이트당 20~25개** 수준이다
(882회 실행 평균 351건은 YC·Techstars 같은 대형 easy-tier가 끌어올린 값).

**이 정정이 계획 전체를 바꾼다: 소수 사이트 재실행으로는 규모가 안 나온다.**

## 1. 원칙 — "stable system" (교수님 요구 반영)

교수님이 국가에 대해 말한 *"custom standard, rather than we collect to claim"* 을
스크래핑 전체에 적용한다.

**원칙 1 — 정의를 먼저 고정한다**
```
확인된 회사 (verified entity)
  = hidden 이면서 (도메인 있음 OR 설명 있음 OR GitHub Organization 확인됨
                  OR VC 포트폴리오 페이지에 게시됨)
현재: 33,061개 + GitHub 확인분
```
수집한 뒤에 세지 않고, **세는 기준을 먼저 정한 뒤 수집한다.**

> **'이름뿐 21,670개'는 한 덩어리가 아니었다** (2026-08-13 실측)
>
> | 갈래 | 수 | 판정 방법 | 해석 |
> |---|---|---|---|
> | 이름에 공백·마침표 있음 | 4,527 | **규칙으로 확정 (호출 0회)** | GitHub 로그인일 수 없음 → "In-Pipe Robot Inc." 처럼 오히려 **회사명 형태**. 웹 보강 대상 |
> | 핸들 형태 | 15,524 | GitHub API 조회 | 절반 정도가 실제 조직 |
> | 그중 VC 포트폴리오 출처 | 1,270 | source_domain 보유 | **VC가 게시했다는 증거** → 도메인 없어도 회사 |
>
> 초기 조회 결과(핸들 형태 713건): Organization 282 · User 316 · 없음 115
> → **해석되는 것 중 47%가 실제 조직.** 예전에 어림한 "2/3은 개인"보다 훨씬 낫다.
>
> **교훈: "데이터가 없다"를 "회사가 아니다"로 읽으면 안 된다.** 갈래마다 증거의
> 종류가 다르므로 판정 방법도 달라야 한다.

**원칙 2 — 모든 값에 출처와 신뢰도를 남긴다**
이미 `company_enrichment.sources` 에 `{field: {source, confidence}}` 로 저장 중.
새로 넣는 필드도 예외 없이 동일하게.

**원칙 3 — 싼 것부터, 비싼 건 마지막에**
| 수단 | 단가 | 적중률 | 순위 |
|---|---|---|---|
| WHOIS | **$0** | 93% | 1 |
| GitHub API | **$0** | 확정적 | 1 |
| ccTLD·LinkedIn URL 파싱 | **$0** | — | 1 |
| 사이트 스크랩 (도메인 이미 앎) | ~$0.003 | 64% | 2 |
| 설명 분류 (Tier 1) | ~$0.0015 | ~100% | 2 |
| **Tavily 검색** | **$0.008** | 낮음 | 3 |
| 에이전트 사이트 크롤 | ~$0.02–0.05 | 사이트당 20건 | 3 |

> **철칙: 도메인을 이미 아는 회사에는 Tavily를 절대 쓰지 않는다.**
> (사이트에 직접 접속하면 되므로 검색비가 0)

**원칙 4 — 예산 가드를 코드에 넣는다**
지금까지 세 번 크레딧이 런 도중에 말라서 몇 시간을 헛돌았다.
각 스테이지가 시작 전에 잔액을 확인하고, 소진되면 **작업을 "완료" 표시하지 않고**
멈추도록 이미 수정했다(LLM 무응답 시 미표시). 여기에 **사전 잔액 체크**를 추가한다.

## 2. Depth — 기존 hidden 정보 채우기

현재 hidden-AI 11,320 기준 커버리지: 분류 64% · 설립연도 45% · product 26% · 창업자 4%

| 단계 | 대상 | 수단 | 비용 | 기대 |
|---|---|---|---|---|
| **D1** | 이름뿐 21,670 | 규칙 4,527 + GitHub API 15,524 | **$0** | 회사/개인 판정 (진행 중, ~3h) |
| **D2** | 도메인만 있는 8,486 | 사이트 스크랩 → 설명 확보 → 분류 | **~$25** | 설명 8,486개 + 분류 |
| **D3** | 도메인 있는 전체 | WHOIS 나머지 | **$0** | 설립연도 45%→60% |
| **D4** | 설명 생긴 것 전부 | Tier 1 재분류 | **~$8** | 분류 64%→85% |
| **D5** | 창업자 | LinkedIn URL 있는 831개만 타겟 | ~$7 | 창업자 4%→10% |

**Depth 합계: 약 $40** → 분류 85%, 설립연도 60%, 설명 +8,500

> D2가 핵심이다. 도메인을 이미 아니까 **Tavily 0원**이고, 사이트에서 설명을 얻으면
> 그 즉시 분류까지 되므로 한 번에 두 칸이 채워진다.

## 3. Breadth — hidden 회사 더 찾기

### 냉정한 계산
에이전트 사이트 1곳 = 약 20~25개 회사.
**+10,000개를 원하면 사이트 400~500곳이 필요하다.** 소수 재실행으로는 불가능.

| 단계 | 방법 | 비용 | 기대 수확 |
|---|---|---|---|
| **B1** | 검증된 미등록 26곳 실행 | ~$3 | ~500 |
| **B2** | 실패 146곳 재시도 (대부분 크레딧 탓) | ~$15 + Tavily $8 | ~1,500 |
| **B3** | 기존 150곳 재수집 (증분) | ~$12 | ~1,000 + **시계열** |
| **B4** | **scout으로 신규 사이트 발굴** | Tavily $25 + LLM $20 | 사이트 +300 → **~6,000** |
| **B5** | GitHub 주간 스캔 | $0 (+판정 $0) | 수천 (단, 품질 낮음) |

**Breadth 합계: 약 $85** → 회사 +9,000~10,000

### B3이 특별한 이유
같은 포트폴리오 사이트를 **두 시점에** 긁으면
"이 VC가 3개월 새 AI 회사를 몇 개 더 담았나"를 볼 수 있다.
교수님이 지적한 *"ours is not longitudinal"* 을 정면으로 해결하는 유일한 수단이다.
→ **증분이 적어도 우선순위를 높게 둘 가치가 있다.**

## 4. 실행 순서와 예산

| 순서 | 내용 | 비용 | 왜 이 순서인가 |
|---|---|---|---|
| **1** | D1 GitHub 판정 + D3 WHOIS | **$0** | 공짜인데 정의(원칙1)를 확정해준다 |
| **2** | D2 + D4 (도메인 있는 것 긁고 분류) | **$33** | Tavily 0원, 커버리지 가장 크게 상승 |
| **3** | B1 + B3 (검증된 26곳 + 재수집) | **$15** | 확실한 수확 + 시계열 확보 |
| **4** | B4 scout 신규 발굴 | **$45** | 규모는 여기서만 나온다 |
| **5** | B2 실패 재시도 / D5 창업자 | **$30** | 불확실 — 마지막 |

**추천 예산:**
- **최소 ($35)** — 1+2단계. 세부정보를 85%까지, 회사 수 증가는 없음
- **권장 ($50)** — 1+2+3. 세부정보 + 시계열 데이터 확보 ⭐
- **확장 ($95)** — +4단계. 회사 수 +6,000
- **전체 ($125)** — 전부

**API별 배분 (권장 $50 기준)**
```
Anthropic  $42   (분류·추출·에이전트 크롤)
Tavily     $8    (신규 사이트 발굴에만, 도메인 없는 경우만)
GitHub     $0
WHOIS      $0
```

## 6. 실행 방법 — 명령 하나

API 키를 넣고 옵션 이름만 고르면 된다. 단계는 **싼 것부터** 순서대로 돌고,
중간에 크레딧이 떨어져도 이미 확보한 커버리지는 남는다 (전 단계 재개 가능).

```bash
export DATABASE_URL='<Railway DATABASE_PUBLIC_URL>'
export ANTHROPIC_API_KEY='...'
export TAVILY_API_KEY='...'          # breadth 단계에만 필요

./scripts/run_scraping_plan.sh free           # $0    지금 바로 가능
./scripts/run_scraping_plan.sh depth          # ~$33  세부정보 채우기
./scripts/run_scraping_plan.sh longitudinal   # ~$15  시계열 확보
./scripts/run_scraping_plan.sh breadth        # ~$45  회사 수 늘리기
./scripts/run_scraping_plan.sh recommended    # free + depth + longitudinal  ⭐
./scripts/run_scraping_plan.sh all
```

각 실행은 시작·종료 시점의 커버리지를 함께 찍고 `logs/plan_*.log` 에 남긴다.
`DATABASE_URL` 이 없으면 **실행을 거부한다** — 오래된 로컬 덤프에 잘못 쓰는 사고 방지.
